# 0.5 · RunRequest / RunResult + finish line

Status: todo
Depends on: 0.1

## Goal
The run is started by a `RunRequest` and ends with a `RunResult`; the normal run can actually end.

## Context
- `scenes/run/game.gd`, `Game.tscn`: ignores `current_world/phase`; outside lab the ground is a fixed 4000 px rect, no kill zone, no finish. Lab death reloads; normal death returns to menu.
- `stages/dev/phase_00_lab.gd` (`DevLabCatalog.build(world)`), `scenes/run/kill_zone.gd`.
- `autoload/EventBus.gd` signals: `player_dashed`, `player_dash_ended`, `player_jumped`, `player_died`, `coin_collected(amount)`, `scene_changed(path)`.

## Scope
- `run/run_request.gd` `{phase_id, mode: official|sandbox|lab, loop_config_id, modifiers}` and `run/run_result.gd` `{phase_id, mode, outcome: cleared|died|quit, time_ms, collectibles[], ...}` per spec §2.3.
- Router route `run` receives `RunRequest` as param; level select and dev lab build one (replaces `current_world/phase`, `is_dev_lab_run` reads).
- EventBus: `run_started(request)`, `run_finished(result)`.
- Normal run: kill zone under the ground + minimal finish line at the end of the 4000 px ground → outcome `cleared`; death → `died`; pause→menu → `quit`.
- With no results screen yet: after `run_finished`, return to `select` (lab keeps reload-on-death).

## Out of scope
Results screen (1.4), `GameLoopConfig` extraction (3.1), scoring.

## Acceptance criteria
- [ ] Every run emits exactly one `run_finished`.
- [ ] Lab still works as before.
- [ ] `GameManager.current_world/phase` no longer read by `game.gd`.

## Minimal tests
Request/result `to_dict/from_dict`, default request validation, outcome mapping helper (pure function).

None.
