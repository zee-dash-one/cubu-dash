# 0.4 · Save schema v1 + migration + PlayerState + debounce

Status: todo
Depends on: —

## Goal
Versioned save with migration from today's file, and writes debounced instead of on every `set_value`.

## Context
- `save/save_port.gd`, `save/file_save_adapter.gd` (`user://save.json`), `save/save_factory.gd` (`make_default()`).
- `autoload/SaveLoad.gd`: holds one `Dictionary`, `set_value` calls `_port.save_data(_data)` every time. Only key used: `"input"` (by `InputManager`).

## Scope
- `save/save_schema.gd`: `CURRENT_VERSION := 1`, `default_data()` with spec §2.2 shape `{version, profile, progress, story{seen}, wallet{soft}, inventory{owned, equipped{skin, trail}}, achievements, leaderboard_local, settings, input}`.
- `save/save_migrator.gd`: v0 (no `version`) → v1 keeping `input` untouched; chain-able per version.
- `autoload/PlayerState.gd`: facade over `SavePort` with typed accessors (`profile()`, `wallet_soft()`, `mark_phase_cleared(...)` etc. only as needed by later tasks; start minimal), `flush()`.
- Debounce (e.g. 0.5 s Timer) + flush on `NOTIFICATION_WM_CLOSE_REQUEST` / tree exit.
- Keep `SaveLoad` API working for `InputManager` (delegate to PlayerState).

## Out of scope
Cloud save, encryption, UI.

## Acceptance criteria
- [ ] Existing `user://save.json` with only `input` loads; controls remap preserved.
- [ ] N rapid `set_value` calls → one write.
- [ ] Corrupt/empty file → defaults, no crash, warning logged.

## Minimal tests
Migration v0→v1, defaults, debounce via an in-memory `SavePort` test double counting writes, round-trip.

## Hypotheses
- D2: `leaderboard_local` is the only leaderboard storage.
