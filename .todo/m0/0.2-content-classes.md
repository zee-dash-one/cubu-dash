# 0.2 · Content classes + GUT

Status: todo
Depends on: —

## Goal
Typed `Resource` classes for content with `from_dict()` / `to_dict()` / `validate()`, plus GUT installed as the test framework.

## Context
- No `content/` or `tests/` folder exists. `stages/` only has `stages/dev/phase_00_lab.gd`.
- Field list: spec §2.2 table.

## Scope
- Install GUT (version compatible with Godot 4.7) under `addons/gut/`, enable the plugin, add `tests/` and a `.gutconfig.json`.
- `content/defs/`: `world_def.gd`, `phase_def.gd`, `story_beat.gd`, `achievement_def.gd`, `cosmetic_item.gd`, `theme_pack.gd`, `game_loop_config.gd`, plus small value types `unlock_rule.gd`, `schedule.gd` if useful.
- Each: `class_name X extends Resource`, `static func from_dict(d: Dictionary) -> X`, `func to_dict() -> Dictionary`, `func validate() -> Array[String]` (empty = valid).

## Out of scope
Loading JSON files (0.3), content data, any UI.

## Implementation notes
- Enum-like fields (`trigger`, `format`, `type`, `acquire`, `schedule.mode`, `unlock_rule.type`) validated against const arrays.
- Unknown keys ignored with no error; missing required keys → validation message `"<Type>.<field> is required"`.
- `StoryBeat.format`: only `cards` is used in M1 (HYPOTHESIS D4) but keep all three values valid.

## Acceptance criteria
- [ ] GUT command from README runs and exits 0.
- [ ] `to_dict(from_dict(d)) == d` for a valid sample of every type.
- [ ] Each type rejects one missing required field and one invalid enum.

## Fallback (Hil, 27/10)
If GUT does not work on Godot 4.7, use any other framework that works (e.g. gdUnit4) without stopping to ask. Log the choice, the reason and the new test command in this file's Log and update the command in `README.md`.

## Minimal tests
`tests/content/test_<type>.gd` per type: round-trip, required field, invalid enum.

## Hypotheses
- D4: story format starts as `cards` before the phase.
- D8 (achievement economy / platform ids) out of M0: keep fields, no logic.
