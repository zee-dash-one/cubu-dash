# 0.7 · ThemeService + slots + ThemeSlot + `default` pack

Status: todo
Depends on: 0.3

## Goal
Visuals resolve semantic slots, so seasonal packs and cosmetics can be added later without code changes.

## Context
- `scenes/run/player.gd` / `Player.tscn`: body is a `ColorRect`.
- Spec §2.5: slots `player.body`, `player.trail`, `world.ground`, `world.bg_far`, `world.hazard.spike`, `ui.title_bg`, `sfx.jump`, `music.world.<id>`.

## Scope
- `theme/slot_registry.gd`: known slot ids + kind (texture/audio/color).
- `autoload/ThemeService.gd`: `resolve(slot) -> Variant` (null = fallback), `active_pack_ids()`, signal `theme_changed`.
- Resolution order: equipped cosmetic (`player.*` only) → active seasonal pack (highest `priority`, schedule evaluated at boot) → world theme (`WorldDef.theme_id`) → `default`.
- `content/theme_packs.json` with `default` pack (no assets yet).
- `theme/theme_slot.gd` component (Node child) that applies the resolved resource to its parent and listens to `theme_changed`.
- Player uses slot `player.body`; with no asset it keeps the current `ColorRect` look.

## Out of scope
Shop/inventory (1.7), `.pck` loading, Studio pack manager (2.5).

## Acceptance criteria
- [ ] Game looks identical with only the `default` pack.
- [ ] A test pack with a texture for `player.body` changes the player when active.
- [ ] Bought cosmetic beats seasonal pack (D6, decided).

## Minimal tests
Resolution order cases, date_range schedule (incl. wrap across year end, e.g. 12-20 → 01-05), unknown slot → null.
